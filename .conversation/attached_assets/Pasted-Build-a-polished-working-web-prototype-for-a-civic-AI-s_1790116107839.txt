Build a polished working web prototype for a civic AI system called “San José Homelessness Safety Reporter.”

IMPORTANT: This is a prototype for a class project, not a real city system. Do not claim that it is officially connected to the City of San José or any real city databases.

PROJECT PURPOSE:
The system helps organize reports about unsafe conditions or problems related to unsheltered homelessness in San José. The main problem is that people have trouble reporting problems clearly and City workers may receive incomplete or unclear information.

The prototype must focus on ONE core AI capability:
STRUCTURED EXTRACTION — turning an unorganized report into a clear structured summary and identifying missing information.

The AI should ASSIST the City worker, not make the final decision. A City employee named Robert must review the AI-generated output before anything is approved or acted upon.

USER FLOW:

1. RESIDENT REPORT PAGE
Create a simple, accessible page where a resident such as “Marcus” can submit a report.

Include:
- Report description text box
- Location/address field
- Issue type dropdown
- Urgency dropdown
- Optional photo upload
- Submit Report button

Example report that can be used:
“There is a large amount of trash and debris blocking the sidewalk near the downtown area. People using wheelchairs and pedestrians have to walk into the street to get around it. I noticed it this morning and it is still there.”

The user should be able to edit the example before submitting it.

2. AI PROCESSING
After clicking Submit Report, show a short AI processing state such as:
“AI is organizing your report…”

Then generate a structured report.

Extract and display:
- Issue
- Location
- Issue Type
- Urgency
- Description
- Previous City Action
- Missing Information

The AI should identify information that is missing instead of inventing information.

For example:
Issue: Blocked sidewalk / debris
Location: Downtown San José
Issue Type: Public safety / accessibility
Urgency: Medium
Description: Sidewalk is blocked by trash and debris.
Previous City Action: Unknown

Missing information:
- Exact street address
- Whether the obstruction is completely blocking the sidewalk
- Whether the issue has previously been reported

Clearly label AI-generated information as “AI Draft.”

3. CITY WORKER REVIEW PAGE
Create a separate dashboard for the City worker “Robert.”

The dashboard should show:
- New Reports
- Report ID
- Date/time
- Location
- Issue type
- AI urgency
- Status

When Robert clicks a report, show the complete AI-generated structured summary.

Include a prominent message:
“Human review required before action.”

Robert must be able to:
- Edit the AI-generated fields
- Correct the issue
- Correct the location
- Change urgency
- Edit the summary
- Change the recommended department
- Request more information
- Approve the report
- Reject the AI recommendation

The AI should NEVER automatically approve, submit, route, or act on a report.

4. RECOMMENDED DEPARTMENT
The AI may suggest an appropriate City department based on the report.

For example:
“Suggested Department: San José Housing Department”

But make it clear that this is an AI suggestion:
“AI Suggested — Requires Human Review”

Robert can change the recommendation before approving.

5. MISSING INFORMATION
Make missing information especially visible.

Use a section called:
“Missing Information”

If required information is missing, display it clearly and explain that Robert can request more information before acting.

Example:
⚠ Missing:
- Exact location
- Whether the sidewalk is fully blocked

Include a button:
“Request More Information”

6. REPORT STATUS
After Robert approves the report, update the status to:
“Human Approved”

Show a simple status timeline:

Report Submitted
↓
AI Structured
↓
Human Review
↓
Approved

Do not make the AI responsible for the final decision.

7. RESIDENT CONFIRMATION
After submission, Marcus should receive a confirmation page.

Show:
“Your report has been received.”

Include:
- Report ID
- Date submitted
- Current status: “Awaiting City Review”
- What happens next

Make it clear that the prototype does not actually send the report to the real City of San José.

DESIGN:
Create a professional civic/government-style interface.

Use:
- Clean white/light background
- Blue and dark navy accents
- Accessible typography
- Large buttons
- Clear cards and sections
- Simple icons
- Good spacing
- Responsive design for desktop and mobile

The design should feel like a modern public-service website rather than a generic AI chatbot.

NAVIGATION:
Create a simple navigation bar with:
- Home
- Submit Report
- My Report
- City Staff Dashboard

Include a small label somewhere:
“Prototype — Not an Official City of San José Service”

IMPORTANT AI BEHAVIOR:
The prototype should demonstrate the concept of structured extraction.

Do NOT build:
- Automatic report routing
- Automatic City actions
- Automatic approval
- Real City database connections
- Real emergency response
- Real-time government integrations
- A full shelter/resource recommendation system

Those are outside the scope of this prototype.

The prototype should demonstrate that AI can:
1. Take an unclear/unstructured report
2. Extract important information
3. Put that information into structured fields
4. Identify missing information
5. Suggest a department
6. Allow a human City employee to review and change the AI output

TECHNICAL REQUIREMENTS:
- Make the prototype fully interactive.
- Use realistic sample data so the prototype works immediately.
- Do not require external APIs or API keys for the basic demo.
- Simulate the AI extraction using predefined logic/sample outputs if necessary.
- Store submitted reports in the browser/local application state so the resident and City dashboard can demonstrate the workflow.
- Include at least one sample report already available for demonstration.
- Make all buttons and navigation work.
- Make the application visually polished and presentation-ready.

DEMO SCENARIO:
The main demonstration should follow this exact sequence:

1. Marcus opens “Submit Report.”
2. Marcus enters a description of a blocked sidewalk and unsafe condition.
3. Marcus submits the report.
4. The system shows “AI is organizing your report.”
5. The AI produces a structured summary.
6. The AI highlights missing information.
7. The system shows an AI-suggested department.
8. Marcus receives confirmation that the report was received.
9. Robert opens the City Staff Dashboard.
10. Robert reviews the AI-generated summary.
11. Robert edits at least one field.
12. Robert either requests more information OR approves the report.
13. The report status changes to “Human Approved” if approved.

Make this flow obvious and easy to demonstrate in a class presentation.

At the top of the City Staff Dashboard, include:
“AI-Assisted Report Review”
“AI organizes reports and identifies missing information. A City employee makes the final decision.”

The prototype should communicate the project's key idea:
“Our prototype proves that AI can turn an unclear report into a structured summary and identify missing information. Full implementation would require city case-history systems, secure integrations, and a reliable process for follow-up updates.”

Build the application now and make sure it runs without errors.
